# JLUSV 地面站上位机 1.1.4 (Qt 5.15.3 C++17)

本子项目是专为无人船 (USV) 打造的桌面端地面站程序，使用支持 C++17 的 Qt 5.15.3 开发。

## 主要特性

1. **高精度遥测展示**：
   - 接收地面站 ESP32 网关（`GET /api/v1/fleet/overview`）提供的位置、对地航速、COG、控制方向及其来源、电量与接收机解状态。
   - 网关 RTK 枚举为 `1=非RTK、2=FLOAT、3=FIXED`；位置来源单独显示，惯性推算不标为FIXED。GS ESP 3.0.92未上报位置来源时显示“来源未提供”，不由解状态推测。
   - 位置、COG与控制方向分别校验；方向无效时地图显示圆点。控制方向来自GPS时标为COG，来自校准磁罗盘时标为艏向，并保留真北/磁北标识。
   - GS 位置读取同一网关的 `GET /api/v1/gs/gnss/receiver`，每秒最多一次，显示 WGS-84 经纬度、坐标来源及源龄；地图显示独立 GS 标记并可点击“定位地面站”。
   - 距 GS、真北方位及东 X / 北 Y（m）使用原始 WGS-84 船位和 GS 坐标，沿用 GS 船舶卡片的计算公式。东/北为正，西/南为负；两端均有有效新鲜坐标时显示。
   - 原点有效性沿用网关主控检查及 GS 页面的坐标/状态源龄上限，计入 HTTP 和客户端等待时间；无效/过期坐标不显示有效标记或相对位置，保留的坐标明确标“旧值”。GS 和船舶地图标记应用同一底图转换，不用转换后的坐标计算米制位置。
2. **高分卫星底图与打点循迹**：
   - 基于 `QtLocation` 与 `QtQuickWidgets`，支持加载吉林一号/高德高分辨率卫星底图；
   - 支持本地离线瓦片缓存（MBTiles 或 XYZ 瓦片目录），并已在 `.gitignore` 中过滤大体积地图文件；
   - 鼠标直接在地图上打点规划循迹折线轨迹。
3. **坐标纠偏引擎 (WGS-84 <-> GCJ-02)**：
   - 按实际底图选择GCJ-02转换；WGS-84底图应关闭。地图显示/点击进行对应转换，手输和下发航点始终保留WGS-84。底图配准误差与接收机定位精度需分别检验。
4. **主控 / 工控任务与执行反馈**：
   - 独立选择目标船只、执行方和任务，应用模式并等待船端实际确认；
   - 两种执行方均支持航向＋航速、航向＋固定推进、1～16个航路点；舵桨模式支持切换，主控操纵沿用网关 `/remote`，工控操纵沿用ROS主题；
   - 默认保留航点各自速度，新增地图点使用面板默认速度；只有勾选统一替换才覆盖整条航线速度；
   - 持续显示操作编号、收件阶段、执行状态、等待/失败原因及可用的航点进度；
   - 停船按钮可抢占正在跟踪的操作，必须有匹配任务阶段和输出关闭证明才显示已停船。

## 使用顺序

1. 配置网关地址和控制密码，点击连接，选择目标船只。
2. 选择主控或工控及任务类型，点击“应用所选模式”。切换会停止当前输出；须等待船端 `MODE_APPLIED`、版本号及命令身份一致。
3. 填写目标方向、航速/固定推进，或在地图上规划/粘贴WGS-84航点。速度范围0～3 m/s，固定推进0～100%，0%仍自动控舵。
4. 发布后查看持续反馈。`202`只表示网关受理，`RP_RECEIVED`只表示船端收件；等待条件和使能阶段不作为执行完成。
5. 停船后仍需查看输出关闭确认。主控通常报告STOPPED；工控可能回到WAITING_IPC，只有相同任务阶段、命令身份及零输出证明匹配才确认停船。

航点未定位、方向/航速过期或工控未就绪时，面板显示等待原因；不能根据地图显示或收件ACK判断实际执行。
切换目标/网关、船端重启会使旧跟踪失效。网络结果不明时只查询原操作编号，不自动重发，不自动恢复旧运动目标。
日志只在状态变化时记录操作编号、收件状态和后端原因。模式/停船确认超过20秒，或连续20秒没有新鲜执行回报时，停止自动跟踪并保留原操作供手动刷新；收件超时不再与执行过期提示交替刷屏。
工控完整GS任务执行需配套RP IPCGS1和NUC jlusv_main_control 0.4.0；源码/模拟测试不能替代实艇闭环验收。

1.1.4新增工控回转与Z型实验。选择实验后执行方固定为IPC；参数包括有符号舵角、固定推进或航速、独立Z阈值、次数及最大时长。回转次数以90°为单位（默认6，即540°）；Z次数为换舵次数，最后一次换舵后继续记录超调，回到初始方向再结束。每次先保持初始艏向5秒，再施加实验舵角；最大时长包含准备及等待时间。

实验要求新鲜定位和直接磁艏向，航速模式另需有效航速。方向源、参考、状态或通信失效即中止，不自动恢复。发布新任务前先停船；完成／中止必须同时有对应任务回报和输出关闭证明。原始Status、Diagnostic及实验阶段保存在船上IPC现有日志，不通过LoRa下载文件。

实验完整链路需GS ESP3.0.99-exp1、GS RP2.2.79-exp1、船RP1.0.204-exp1及IPC0.4.5配套；固定帧布局保持。普通航向／航迹仍使用原控制与选源规则。离线检查通过不代表已部署或已完成实艇实验、水动力参数辨识。

## 构建与运行

### 依赖环境
- **编译器**：MSVC 2022 (msvc143_x64) 支持 C++17
- **Qt 版本**：Qt 5.15.3 64-bit (路径通常为 `E:\Qt\5.15.3\msvc143_x64`)
- **构建工具**：CMake >= 3.16，沿用本库现有Visual Studio 2022 x64构建目录

### CMake 构建命令示例 (PowerShell)
```powershell
$env:Qt5_DIR = "E:\Qt\5.15.3\msvc143_x64\lib\cmake\Qt5"
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH=E:/Qt/5.15.3/msvc143_x64 -DBUILD_TESTING=ON
cmake --build build --config Release --parallel 8
ctest --test-dir build -C Release --output-on-failure
```

在VS 2022 x64开发环境中执行。测试仅访问127.0.0.1的临时模拟网关；QtTest详情写入构建目录的 `gs-client-tests.txt`。
唯一交付入口为本库已有的 `build/Release/jlusv_gsapp.exe`，Qt/QML/MSVC依赖保持在同目录。
直接双击EXE即可，地图服务按EXE位置找到本库 `maps/tiles`（相对Release目录的 `../../maps/tiles`），不依赖启动工作目录或额外脚本，不复制地图资产。

复制到另一台Windows x64电脑时，执行 `python tools/package_portable.py`，使用生成的 `build/portable-dist/JLUSV-GSApp-1.1.4-Windows-x64-portable.zip`。完整解压后双击其中EXE；不要只复制EXE。便携包包含Qt/QML/地图插件、MSVC运行库、相对路径qt.conf及现有离线瓦片，地图覆盖范围与原机相同；无需安装开发环境，仍需正常显卡驱动。包内不带控制密码或设备会话。
